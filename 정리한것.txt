# 1단계: 현재 React Vite 쇼핑몰 프로젝트 분석

## 1. 현재 폴더 및 폴더 구조

### 루트
- `src/`: React 화면, 컴포넌트, 스타일, 향후 Firebase 연동 구조
- `public/`: 브라우저가 직접 제공하는 이미지·영상·JSON 데이터
- `public/data/`: 배너, 카테고리, 상품, 상세 상품 정보 JSON
- `node_modules/`: 설치된 패키지
- `docs/`: 프로젝트 문서
- `dist/`: 기본 빌드 결과물
- `historyCode.txt`: 수정 이력
- `package.json`: React, React Router, Sass, model-viewer 의존성 및 명령어
- `.env.example`: Firebase 환경변수 이름 예시만 존재

### src 구조
- `pages/`: 페이지 단위 컴포넌트. 각 페이지는 기본적으로 같은 이름의 `.module.scss`를 사용함.
- `components/`: 재사용 UI 컴포넌트. 대부분 같은 이름의 `.module.scss`를 사용함.
- `styles/`: `reset.scss`, `global.scss` 전역 스타일
- `firebase/`: Firebase 초기화 및 auth/product/order/storage/user API 파일의 자리만 마련됨. 현재 내용은 주석 수준임.
- `store/`: auth/cart/order/product/wishlist/loading 상태 파일의 자리만 마련됨. 현재 Zustand 구현은 없음.
- `hooks/`: 도메인별 커스텀 훅 파일의 자리만 마련됨.
- `constants/`: 라우트, 색상, 카테고리 등 상수 파일
- `utils/`: 가격, 날짜, 유효성 검사, 저장소 등 유틸 파일
- `assets/`: 폰트와 정적 에셋

## 2. 상품 JSON을 불러오는 위치

주 상품 데이터는 `public/data/products-fixed.json`이며, 다음 위치에서 직접 `fetch`로 불러옵니다.

- `src/pages/Home.jsx`: 상품 목록 중 앞 4개를 홈의 Our Picks에 표시
- `src/pages/Products.jsx`: 상품 목록 페이지에 표시
- `src/pages/ProductDetail.jsx`: `products-fixed.json`과 `subDetail.json`을 함께 불러와 상세 화면 구성
- `src/pages/SearchResult.jsx`: 검색 결과를 위해 전체 상품 목록을 불러옴

관련 JSON:
- `public/data/products-fixed.json`: 현재 주 상품 목록
- `public/data/subDetail.json`: 상품 상세 설명 등 추가 정보
- `public/data/categories-fixed.json`: 카테고리 메뉴·필터
- `public/data/banners.json`: 메인 배너

## 3. 로그인과 회원가입을 불러오는 위치

- 로그인 화면: `src/pages/Login.jsx`
- 회원가입 화면: `src/pages/SignUp.jsx`
- 라우트 연결: `src/App.jsx`
  - `/login` → `Login`
  - `/signup` → `SignUp`

현재 두 화면은 폼 UI와 `preventDefault()`만 구현되어 있습니다. 실제 이메일/비밀번호 로그인, 회원가입, 소셜 로그인은 아직 Firebase Auth 또는 다른 인증 서비스와 연결되어 있지 않습니다.

## 4. 라우터 구조

라우터는 `src/App.jsx`에서 `react-router-dom`의 `BrowserRouter`, `Routes`, `Route`로 구성되어 있습니다.

- `/`: Home
- `/login`: Login
- `/signup`: SignUp
- `/wishlist`: Wishlist
- `/cart`: Cart
- `/order`: Order
- `/notice`: Notice
- `/notice/:id`: NoticeDetail
- `/products`: Products
- `/products/:id`: ProductDetail
- `/products/category/:category`: Products
- `/search/:keyword`: SearchResult
- `*`: NotFound

`Admin`, `AdminProduct`, `AdminOrder`, `MyPage`, `OrderComplete` 페이지 파일은 존재하지만 현재 `App.jsx` 라우트에는 연결되어 있지 않습니다.

## 5. Zustand 사용 여부

현재 Zustand는 사용하지 않습니다.

- `package.json`에 `zustand` 패키지가 없음
- `src/store/`의 `authStore.js`, `cartStore.js`, `productStore.js` 등은 주석만 있는 빈 구조
- `src/hooks/`의 도메인별 훅도 실제 구현 전 상태

따라서 전역 상태가 필요해질 때는 Zustand를 설치한 뒤 기존 `src/store/` 구조를 활용하는 방식이 자연스럽습니다.

## 6. Firebase 연결 시 수정할 파일

Firebase 기능 범위에 따라 다음 파일을 수정·추가합니다.

### 공통 초기화와 환경변수
- `package.json`: `firebase` 패키지 추가
- `.env.example`: 필요한 환경변수 이름만 추가 또는 보완. 실제 값은 절대 기록하지 않음.
- `src/firebase/firebase.js`: Firebase App, Auth, Firestore, Storage 초기화 및 export

### 인증
- `src/firebase/authApi.js`: 이메일 회원가입, 로그인, 로그아웃, 인증 상태 함수
- `src/pages/Login.jsx`: 입력 상태, 유효성 검사, 로그인 요청, 오류 UI 연결
- `src/pages/SignUp.jsx`: 입력 상태, 유효성 검사, 회원가입 요청, 오류 UI 연결
- `src/store/authStore.js` 또는 `src/hooks/useAuth.js`: 로그인 사용자와 로딩 상태 구현
- `src/components/ProtectedRoute.jsx`: 로그인 보호 라우트 구현
- 필요 시 `src/components/AdminRoute.jsx`: 관리자 권한 확인 구현

### 상품·주문·공지·이미지
- `src/firebase/productApi.js`: Firestore 상품 조회/등록/수정/삭제
- `src/firebase/orderApi.js`: 주문 생성·조회·상태 변경
- `src/firebase/noticeApi.js`: 공지 CRUD
- `src/firebase/storageApi.js`: 상품 이미지 업로드·삭제
- 해당 페이지 및 관리자 페이지: `Products`, `ProductDetail`, `AdminProduct`, `AdminOrder`, `Notice` 등

### 보안 규칙
- Firestore 보안 규칙: 로그인 사용자 데이터, 관리자 쓰기 권한, 공개 상품 조회 범위를 정의
- Storage 보안 규칙: 관리자 업로드·삭제 권한과 공개 이미지 읽기 범위를 정의
- Firebase 기능을 실제 적용할 때는 테스트 방법과 함께 적용한 보안 규칙 코드를 `historyCode.txt`에 기록해야 함.

## 7. 기존 기능을 유지하며 작업할 순서

1. 수정 대상 페이지·컴포넌트·스타일을 먼저 읽고 현재 동작을 확인한다.
2. 데이터 흐름을 확인한다. 현재 상품 화면은 JSON `fetch`를 유지하며, Firebase 전환은 별도 단계로 분리한다.
3. 필요한 범위의 JSX만 수정한다. 기존 React 함수형 컴포넌트 작성 방식과 import 구조를 유지한다.
4. 기존 Sass Module 방식을 유지한다. 새 스타일은 해당 컴포넌트/페이지의 `.module.scss`에 최소로 추가한다.
5. 데스크톱과 모바일 레이아웃을 함께 확인한다. 기존 미디어 쿼리를 우선 활용하고, 반응형 변경이 필요하면 해당 Sass Module에 `@media` 쿼리를 추가한다.
6. Firebase 연동 시 환경변수 실제 값은 코드·문서·이력에 기록하지 않는다. 기능별 API 파일, 상태 관리, 화면 연결, 보안 규칙을 한 단위로 구현한다.
7. 빌드 또는 관련 검증으로 오류를 확인하고, 오류가 있으면 수정한 뒤 결과를 보고한다. 오류 원인과 수정 내용은 필요한 경우 코드 주석 및 `historyCode.txt`에 남긴다.
8. 수정·추가·생성한 파일과 이유를 `historyCode.txt`에 단계별로 기록한다.
